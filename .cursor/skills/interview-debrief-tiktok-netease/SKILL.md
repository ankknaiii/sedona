## 听音：两岗在验什么

| 岗位 | 他们要听到的 |
| --- | --- |
| TikTok 产品内容设计师 | 产品内文案/内容能改行为；用可量化用户行为定义内容质量；和 PM/Design/Legal/L10n 对齐；TikTok 与 X 的产品差异说得清 |
| 网易游戏产品经理 | 官网/活动是转化产品不是品牌册；宣发期交互能预约、下载、裂变、回访；对目标游戏做过有效 research，不是只背世界观 |

默克经历必须先翻译成对方听得懂的产品语言，再进项目细节。翻译口径见 [merck-pack.md](merck-pack.md)。

## 口播纪律

1. 先一句结论，再 2–4 句证据，停。
2. 数字 > 形容词。没有数就说「当时没有这个口径，我用的是 X」，不要编。
3. 不会就说不会，补「我回去会查的两件事」。
4. 官网题禁止停在「背景故事好看」。至少答：用户来官网要完成什么、关键路径、一个可改的交互、一个衡量指标。
5. 被追「这不是基础吗」时，立刻升一层：基础之上的转化、留存、裂变、风控。

## 单题输出

```markdown
## [原题]
**听音：** 一句话
**满分口播：** 45–90 秒，可直接读
**被追问：** 2 个追问 + 短答
**缺口：** 缺事实 / 缺 research / 缺指标，写下一步
```

## 一次复盘产出

按这个顺序，不要先写长文总结：

1. 默克 60 秒版（部门定位 + OKR + 你负责的官网部分 + 对接角色）
2. 简历 walkthrough：每段经历 40 秒，STAR，带一个行为指标
3. 已记录题目：逐题满分口播（用 [answer-bank.md](answer-bank.md)，按 `profile.md` 替换 `[需补]`）
4. 两岗对照：同一经历分别怎么讲给 TikTok / 网易
5. 迭代清单：按 [prep-iteration.md](prep-iteration.md) 给出本周要补的 research、口径、模拟题

Go through 简历时，每段只问四件事：这是什么产品、你改了哪条用户路径、用什么行为定义好坏、跨部门你推过什么。
